# prd-harness 사용 예시

## 부르기

- `prd-harness`, `정책서 쓰자`, `PRD 만들어줘`, `기획부터 하자`
- 목표/가설/제품 형태를 한 줄로 던져도 됨

---

## 예시 1: 생성

**입력**
> 호텔형 룸타입에서 임박일 오버북이 사고를 낸다. 가설은 "기간·규모·비율 게이트를 통과할 때만 초과 판매하면 입실 실패가 줄어든다". 형태는 예약 생성 시 재고 한도 검사 + 어드민 설정.

**에이전트**
1. `wiki/decisions/` ADR과 모순 없는지 확인 (필요 시 adr-harness)
2. 정책서 `wiki/prd/overbook-gates/policy.md` 작성
3. 승인 요청
4. 승인 후 PRD `wiki/prd/overbook-gates/prd.md`
5. Evaluator 서브에이전트 채점
6. 피드백 루프

정책서가 Acquisition("신규 설치를 늘리자")으로 시작하면 되돌린다.

---

## 예시 2: 평가만

**입력**
> `wiki/prd/overbook-gates/prd.md` 평가해줘

채점표 + 개선 지시만. 자동 보강은 요청 후에.

---

## 예시 3: 나쁜 성공 정의 → 고치기

**나쁨 (Action)**
- 오버북 UI를 만든다
- 재고 API를 추가한다

**좋음 (Result)**
- 호텔형 예약에서 게이트 미통과 초과 판매가 0건이 되고, 입실일 D-1 실방 부족 사고가 월 N건 → 0건
- 특정방 예약에서 이중 판매(같은 유닛·날짜)가 0건
